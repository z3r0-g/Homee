# Homee AI Agent Platform
> Designed to run on repurposed Mac Mini A1347 Metal.

![Homee](UI/static/homee.png)

## Overview

Homee is a simple, self-hosted home for local AI — a lightweight, offline-first alternative to Open WebUI for the house, built for the casual home enthusiast and designed to run on a repurposed Mac Mini. It keeps the loved essentials (chat with bots, tools, scheduled tasks, local Ollama models) and leaves out the clutter: no workspaces, complex admin panels, or fragile plugin stores. The design rule is simple: if a feature needs a manual, it doesn't ship.

***WARNING*** This platform was designed with AI coding agents as a key component of the development workflow to provide a comprehensive system for managing AI agent bots on lightweight hardware with the following in mind:

- **Bot Management**: Create, manage, and chat with AI agent bots with assigned skills and MCP tools
- **1-Click MCP Marketplace**: Connect to Model Context Protocol servers (GitHub, Slack, Google Sheets, Fetch, Postgres, Weather, Local Filesystem, etc.) with automatic endpoint resolution and auth warnings
- **Official Registry & Smithery Sync**: Live synchronization with the Official MCP Registry API (`registry.modelcontextprotocol.io`) and Smithery, with zero-hang offline fallback
- **Skills**: Loadable skills from local directories or remote Git repositories
- **Multimodal AI**: Vision image attachment support and inline rendering for images generated by MCPs and Skills

## Features

Seven features, done the simple way:

1. **Chat with multiple bots, flip while they work** — Every bot lives in the sidebar with a live status word. Send a message or run a task, switch to another bot, and the first task keeps running in the background; its reply is waiting when you come back.
2. **1-Click MCP Marketplace & Smithery Sync** — Browse servers from the Official MCP Registry and Smithery. Non-auth servers install in one click with endpoints automatically resolved; servers requiring keys clearly display an Auth Warning tag and only prompt for credentials when needed. Refresh anytime via the UI Sync button.
3. **Bots strictly use their assigned Skill & MCPs** — Every chat and task execution invokes the bot's configured skill persona and generates callable tool specifications for all assigned and enabled MCP servers.
4. **Multimodal images in chat** — Chat UI renders images created by MCPs and Skills (markdown `![alt](url)`, data URIs, image links) in clean, responsive figures. When a vision-capable model is selected (e.g. `gemma3`, `llava`, `qwen2.5vl`), users can upload images directly into the chat.
5. **Starter prompts on empty chats** — A new chat suggests up to two openers — the bot's own task prompt, if it has one, and "What can you do?" — so a first-time user never faces a blank box.
6. **Fast / Smart model switch** — One switch in the composer: Fast answers with your primary local model, Smart with your configured secondary model. (Smart is enabled once a secondary model is set in Settings.)
7. **Ask about a file or image** — Attach text files or images to a chat (paperclip in the composer) and their contents ride along as context for that conversation.

## Prerequisites

- Apple Mac Mini A1347 Metal w/Ubuntu 22.04 LTS (or similar hardware / OS)
    - 8GB+ RAM (supports running CPU-only LLM models)
- Ollama (local LLM backend)
- Python 3.12+ with virtual environment (`venv`)
- Git (for remote skill plugins)
- Node.js and npm (optional, for frontend assets)

## Architecture

> The platform is organized into two Flask services, each using the **App Factory pattern** (`create_app()` factory), running on separate ports.

### UI Service — `UI/` (port 5001)

**Files:**
- `UI/__init__.py` — empty package marker
- `UI/app.py` — `create_ui_app()` Flask app factory + module-level `app` for WSGI deployment
- `UI/config.py` — paths, ports, defaults
- `UI/models.py` — Bot, Skill, BotConfig + repos
- `UI/llm.py` — LLMRouter: local Ollama (priority) + remote fallback
- `UI/registry_sync.py` — Official MCP Registry and Smithery sync engine with auto-resolution
- `UI/scheduler.py` — stdlib background scheduler for timed bot runs
- `UI/routes/` — Flask blueprints (bots, skills, mcps, knowledge, settings)

**Key Endpoints:**
- `GET /api/bots` — List all bots
- `POST /api/bots` — Create new bot (with assigned skill + schedule)
- `POST /api/bots/{id}/chat` — Chat with bot (uses assigned skill, MCP tools, and multimodal attachments)
- `POST /api/bots/{id}/run` — Run bot's scheduled task
- `GET /api/mcp/remote` — Synced MCP marketplace from Official MCP Registry & Smithery
- `POST /api/mcp/import/{id}` — 1-click install remote MCP (with auto-resolved endpoint and credentials)
- `POST /api/mcp/sync` — Sync MCP registry with Official Registry and Smithery
- `GET /api/skills/marketplace` — Skills marketplace synced from Smithery
- `POST /api/skills/sync` — Sync skills marketplace from Smithery
- `GET /api/skills/active` — Active skills list
- `GET /api/llm/status` — Ollama status and installed models
- `GET /api/health` — Health check

### MCP Service — `MCP/` (port 5002)

**Files:**
- `MCP/__init__.py` — empty package marker
- `MCP/app.py` — `create_mcp_app()` Flask app factory + module-level `app` for WSGI deployment
- `MCP/config.py` — paths, ports, marketplace definitions
- `MCP/routes.py` — MCP CRUD + marketplace + agent-callable execution endpoint forwarding auth headers
